yw01 — the mode-bit witness (kasumi, 2026-10-19, wolf 0.2.33 pin 85dab5d,
wolf-std cceda63). Built: mode-enter / mode-opost on the release tier;
c-raw with `cc -O2 -std=c11`. Driven under a PTY the driver owns
(notes/yw01-evidence/witness/drive.py, python3 -I).

    $ python3 -I drive.py enter target/witness/c-raw
    enter target/witness/c-raw: read='13'
    $ python3 -I drive.py enter target/witness/mode-enter
    enter target/witness/mode-enter: read='10'
    $ python3 -I drive.py opost target/witness/c-raw
    opost target/witness/c-raw: wire=0a
    $ python3 -I drive.py opost target/witness/mode-opost
    opost target/witness/mode-opost: wire=0d0a

Reading:
- ENTER. The PTY master wrote CR (0x0D). C yew, which clears ICRNL
  (sagitta src/term/tty.c:523), read 13 = CR: Enter is a key distinct
  from Ctrl-J. The wolf port, whose raw mode is std.term's `raw` over
  `os_term_set_mode` and so cannot reach ICRNL ([os.term.mode] has no
  bit for it), read 10 = LF: Enter arrives as Ctrl-J. PREDICTION HIT.
- OPOST. The child wrote one LF (0x0A). C yew, which clears OPOST
  (tty.c:528-531), put 0x0A alone on the wire. The port, which cannot
  reach OPOST, left the PTY default (OPOST|ONLCR) on and put 0x0D 0x0A
  (CRLF) on the wire. PREDICTION HIT.

The gap is `os_term_set_mode`'s: the mode int reaches ICANON, ECHO,
SIGNALS (ISIG), FLOW (IXON), EXTENDED (IEXTEN), VMIN and VTIME, and
"every other field of the terminal's settings is left as it is found"
([os.term.mode]). ICRNL, OPOST, ISTRIP, BRKINT, PARMRK, INPCK and the
CS8 set have no bit, so the port cannot express C yew's raw mode. Filed
as the [os.term.mode] widening (Issues). NOT a yw01 blocker (§5): no
campaign-01 golden sends CR as input nor emits a bare LF in paint
output, so the witnessed divergence does not reach a campaign-01 golden;
it would bite yw03 (Enter in the editor) and any output path that emits
`\n`, which the renderer does not.
