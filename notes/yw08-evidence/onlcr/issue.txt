Title: Expose ONLCR in the terminal output-flag surface for raw REPLs

wolf 0.2.35 (wolfgang, pin cf0c13d), Linux x86-64, released archive.
crates/wolf_rt/src/term.rs:212-215 at v0.2.35 clears or sets OPOST via
mode::RAW_OUTPUT but never reads or sets ONLCR. The public mode word has
no ONLCR bit.

The Fletch REPL needs raw input with OPOST|ONLCR enabled, not byte-exact
output: scripts can print through io.print and io.eprint, so translating
only the prompt's own output is insufficient. Pinned C yew implements
this in sagitta 9ace98c2 src/term/tty.c:514-531.

Witness: yew notes/yw08-evidence/onlcr/probe.py. It creates only its own
child PTYs, clears ONLCR before each child execs, waits for the prompt,
then sends import io, io.print("ONLCR-A\nONLCR-B"), and :quit. Both exit 0.
C emits ONLCR-A CR LF ONLCR-B; the wolf port emits ONLCR-A LF ONLCR-B.
The port sets RAW_OUTPUT=0, which enables OPOST but cannot repair ONLCR.
With ordinary default PTY settings the pinned REPL goldens pass.

Requested surface: an os_term output-flag surface carrying ONLCR, or a
raw/opaque termios word that can be saved, changed, and restored. Preserve
the caller's original ONLCR on every exit, including the runtime restore
registration. Test with ONLCR initially both on and off, on the checked
and native tiers. No stty subprocess workaround is implemented in yew.

This is yew MAP G55. The orchestrator files this issue; the lane does not.
